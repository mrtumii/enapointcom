Meter integration

Prepaid meter data & control

ENA Plus prepaid meters report to an on-site Acrel gateway, which forwards to the Acrel IoT EMS cloud (iot.acrel-eem.com). Readings and alarms flow into ENA, and ENA switches, refreshes and tops up meters back through Acrel’s prepayment API.

Meters ─Modbus/LoRa─▶ Acrel gateway ─▶ Acrel IoT EMS ──Data Forwarding──▶ ENA  (HTTPS or MQTT)
                                              ▲                                │ stores readings + alarms
                                              └──── /basic/prepayment ◀────────┤ switch · refresh · top-up
                                                                               ▼
                                         /meter page · staff console · partner API (/api/v1)

1 · Inbound: Acrel Data Forwarding

Configure one of two delivery routes on the Acrel forwarding rule. Both accept the same payloads and are stored identically.

Option A — HTTPS push (recommended)

SettingValue
URLhttps://www.enapoint.com/api/v1/acrel/ingest
MethodPOST, JSON body
AuthAuthorization: Bearer ena_live_… (write scope), or append ?key=ena_live_… if the forwarder can’t set headers
Response{ "success": "1", "readings": n, "events": n }

Option B — MQTT broker

ENA reads the broker once a minute using a persistent session (client id ena-netlify-drain, clean session off, QoS 1), so the broker must retain queued messages for offline sessions — standard on Mosquitto, EMQX and HiveMQ.

SettingValue (example)Notes
Host / portmqtts://mqtt.enapoint.com:8883TLS strongly recommended
Username / passwordacrel-forwarder / •••••Dedicated credential for the forwarder
QoS1At-least-once, per Acrel spec
Real-time topicena/acrel/meter/realtimeArray of meter readings
Event topicena/acrel/meter/eventAlarm / event objects

Payloads are shape-detected, so a message on the “wrong” topic is still parsed: a reading has meterSn plus electrical fields, an event has a list[].

2 · ENA meter API

Same base URL and keys as the rest of the partner API. A meter is addressed by its ENA meter number or its Acrel serial; link the two with PATCH /api/v1/meters/:number and { "acrelMeterSn", "acrelGatewaySn" } when they differ.

MethodPathPurposeAccess
GET/api/v1/meters/:number/liveLatest snapshot. Public: online state, remaining kWh, load and energy. With a key: gateway and every labelled metric.public / read
GET/api/v1/meters/:number/readings?limit=100Recent readings, newest first (kept 90 days).read
GET/api/v1/meters/:number/events?limit=100Alarms for one meter.read
POST/api/v1/meters/:number/controlRemote control. Body { action, amount?, gatewaySn? }; action is on, off, force-on, force-off, refresh, maintenance-start, maintenance-end or topup (with amount). Every command is logged.write
GET/api/v1/telemetryEvery reporting meter with fleet counts (online, offline, alarms in 24 h).read
GET/api/v1/telemetry/events?meter=&limit=100Alarms across the fleet.read
POST/api/v1/acrel/ingestAcrel Data Forwarding receiver (see above).write

A meter is reported online only when its last message said ONLINE and arrived in the past 30 minutes.

3 · Outbound: Acrel prepayment control

ENA signs in to /basic/prepayment/auth_user/login with an AES-128-CBC (zero padding, Base64) encrypted credential, caches the token, and posts commands to /entry/home/control with a token header, re-signing in once on a token error.

ActionAcrel methodValue
on / offSWITCH{"Switch":"1"} / "0"
force-on / force-offFORCESWITCH{"ForceSwitch":"1"} / "0"
refreshREFRESH{}
maintenance-start / -endRLYREP{"RlyRep":"1"} / "0"
topupTenant-specific (default SETPARAM){"SaleMoney":"<amount>"}

The top-up method name varies by Acrel tenant; confirm it in the sandbox. Error 5006 means the purchase amount was rejected.
