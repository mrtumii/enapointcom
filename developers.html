Partners & API

Integrate with ENA metering and payments

A versioned REST API for banks, payment platforms, distribution companies, regulators and government agencies. Register meters, price and settle top-ups, and follow vending — with scoped keys, JSON everywhere and a request ID on every response.

Request partner accessAPI referenceOpenAPI spec

Who connects to ENA

Banks & fintechs

Sell units from your app, USSD or branch channels. Quote, initialise and verify top-ups, and receive the backup token in the response.

Distribution companies

Push verified customer meters straight into the register and keep tariff bands and meter status in sync with your records.

Government & parastatals

Read-only keys for programme monitoring: registered meters, vending volumes and platform health, for reporting and oversight.

How access works

  1. Request access

    Tell us your organisation and use case. We agree scopes and issue a test key the same week.

  2. Build against test

    Test keys (ena_test_…) never move real money. Every route behaves exactly as it does in production.

  3. Go live

    After a short review we issue a live key (ena_live_…). Keys are rotated every 90 days and can be revoked instantly.

API reference

Unversioned /api/… paths remain available, but new integrations should use /api/v1. The machine-readable description is at /openapi.json.

Meters

MethodPathPurposeAccess
POST/api/v1/meters/registerRegister a customer meter. With a write-scoped key the meter is recorded as verified.public / write
POST/api/v1/meters/verifyCheck whether a meter number, IMEI or RFID is already registered.public
GET/api/v1/meters/:numberMeter status and tariff. Holder details and recent tokens with a key.public / read
PATCH/api/v1/meters/:numberUpdate status (verified, suspended…), DisCo or tariff.write
GET/api/v1/meters?status=pending-verificationList registered meters, filterable by status.read

Payments & vending

MethodPathPurposeAccess
POST/api/v1/payments/quotePrice a top-up: units, service charge and tariff for an amount.public
POST/api/v1/payments/initializeCreate an order and return the checkout URL.public
GET/api/v1/payments/verify/:referenceVerify an order, settle it and return the token.public
POST/api/v1/payments/webhookPayment provider callback, signature-verified.signed
GET/api/v1/vendVending log with queued and delivered tokens.read
POST/api/v1/vend/flushDeliver queued units when a meter reconnects.write

Register a verified meter · partner key

curl -X POST https://www.enapoint.com/api/v1/meters/register \
  -H 'authorization: Bearer ena_live_…' \
  -H 'content-type: application/json' \
  -d '{"meterNumber":"45128890231","holderName":"Amaka Okonkwo",
       "email":"amaka@example.com","phone":"08030000000",
       "address":"12B Gado Nasko Way, Apo","state":"FCT Abuja",
       "disco":"AEDC","tariffBand":"B","meterType":"single-phase"}'

Security

TLS only. Keys are stored as SHA-256 hashes and shown once. Write access is a separate scope. Personal data (names, phones, addresses) is only returned to authenticated callers, and processing follows the NDPR.
